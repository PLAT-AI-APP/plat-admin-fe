# 운영 처리 기준 (클로즈베타 초안)

콘솔로 신고·문의·환불·보상을 처리하는 사람이 보는 문서다. **법에서 기한이 정해진 것**은 그대로 따르고,
나머지 기한(표의 `확인 필요`)은 운영 책임자가 정해 이 문서를 고친다.

## 0. 매일 확인

| 어디서 | 무엇을 |
|---|---|
| 헤더 벨·사이드바 뱃지 | 답변 대기 문의(Q&A), 신고된 채 노출 중인 댓글, 검토 대기 신고 건, 발송 대기 상품권 교환 |
| Slack 운영 채널 | 새 1:1 문의, 새 신고 건(같은 대상의 추가 신고는 알리지 않는다), 결제 지급 중단, 메일 실패 |
| 대시보드 | 어제 대비 가입·대화·결제·크레딧 사용. 급변하면 원인을 본다 |

알림 제목 앞의 `plat-be-prod-*` / `plat-be-dev-*` 로 어느 서버 알림인지 구분한다.

## 1. 신고

### 우선순위와 기한

| 사유 | 첫 판정 기한 | 비고 |
|---|---|---|
| 미성년자 성적 콘텐츠 (`MINOR_SEXUAL`) | **즉시(발견 당일)** | 대상 조치 + 피신고자 영구 정지를 기본으로 검토. 필요하면 수사기관 신고(방송통신심의위원회·경찰청) |
| 명예훼손·사생활 침해 (`DEFAMATION`) | 접수 후 지체 없이 — 아래 임시조치 절차 | 정보통신망법 제44조의2 |
| 개인정보 노출 (`PERSONAL_INFO`) | 당일 | 노출된 정보를 먼저 가린다(댓글 숨김·세계관 삭제) |
| 실존 인물 사칭 (`IMPERSONATION`) | `확인 필요`(권장 2영업일) | |
| 그 밖의 사유 | `확인 필요`(권장 3영업일) | |

### 판정

- **조치함**은 대상 조치(댓글 숨김·세계관 삭제) 또는 피신고자 제재가 하나 이상 있어야 닫힌다. 없으면 **위반 없음**.
- 닫힌 케이스는 다시 열리지 않는다. 같은 대상이 다시 신고되면 새 케이스가 되고, 상세의 "지난 케이스"에 이력이 보인다.
- 처리 메모는 제재 사유로 유저에게 남는다. 확인 가능한 근거로 쓴다.
- **AI 답변 신고**: 원본은 신고자의 개인 대화라 콘솔에서 열지 않는다. 스냅샷(신고자 메시지 + AI 답변)으로 판단한다.
  대상 조치는 없다 — 유도된 답변이면 위반 없음, 세계관 설정이 원인이면 제작자 제재 또는 해당 세계관 신고 건으로 조치한다.
  프롬프트·모델 문제는 개발 채널로 넘긴다.

### 임시조치 (정보통신망법 제44조의2)

권리를 침해당했다는 사람이 삭제를 요청하면:

1. 요청자와 침해 내용을 확인한다(신고 상세·1:1 문의).
2. 판단이 어렵거나 다툼이 예상되면 **30일 이내 임시조치** — 댓글은 숨김으로 내린다.
   세계관은 콘솔에 "숨김"이 없고 삭제만 있다 → 삭제 전에 운영 책임자 확인. (`확인 필요`: 세계관 임시 비공개 기능 필요 여부)
3. 게시자에게 조치 사실을 알린다(1:1 문의 답변 또는 이메일).
4. 게시자가 이의를 제기하면 재검토하고, 30일 안에 결론이 없으면 원칙대로 처리한다.
5. 처리 과정을 신고 케이스 메모에 남긴다.

## 2. 1:1 문의

| 유형 | 답변 기한 | 비고 |
|---|---|---|
| 환불 (`REFUND`) | 아래 3장 | 환불 요청으로 자동 생성된다. 유저가 직접 쓸 수 없는 유형 |
| 결제·계정 | `확인 필요`(권장 1영업일) | |
| 버그 (`BUG`) | `확인 필요`(권장 2영업일) | 베타 안내 띠의 "버그 제보"가 이 유형으로 연다. 재현되면 개발 채널로 |
| 그 밖 | `확인 필요`(권장 2영업일) | |

- 답변은 사람이 쓴다. 환불 결과를 문의 답변에 자동으로 붙이지 않는다(환불 화면에서 처리하고, 답변에는 안내만 쓴다).
- 답변에 다른 유저의 개인정보를 쓰지 않는다.

## 3. 환불 (전자상거래법 제18조)

- 청약철회로 환불이 확정되면 **3영업일 이내에 환급**해야 한다. 늦으면 지연 이자 대상이 된다.
- 현재 정책: 노트를 하나도 쓰지 않은 결제만, 결제 후 7일 안에 전액 환불. (정책 자체는 법무 검토 중 — D7)
- 처리 순서: 유저가 환불을 신청하면 환불 문의가 생긴다 → 결제 관리 → 해당 주문 상세 → **환불 승인**(또는 거절).
  승인하면 PG 취소가 나가고, 신청 뒤 노트를 쓴 경우는 서버가 자동으로 거절한다. **신청일부터 3영업일 안에 승인까지 끝낸다.**
- PG 쪽에서 이미 취소했는데 서버에 반영되지 않았으면 주문 상세의 수동 취소 기록(경위 필수)을 쓴다.
- 실패하면 주문 상태와 Slack 알림을 보고 다시 실행한다. 이미 끝난 환불은 두 번 실행되지 않는다.

## 4. 보상·크레딧

- 한 명: 크레딧 조정 → 크레딧 조정. 사유에 CS 티켓 번호처럼 확인 가능한 근거를 쓴다.
- 여러 명(베타 보상·장애 보상): 크레딧 조정 → **일괄 지급**. 한 번에 500명, 한 명당 100,000까지.
  - 결과에 실패한 유저가 있으면 **같은 모달에서** "실패한 유저만 다시 시도"를 누른다. 같은 묶음 키라 이미 받은 유저는 건너뛴다.
  - 모달을 닫고 새로 열면 새 묶음이 된다 — 같은 명단을 새 모달로 다시 보내면 **두 번 지급된다**.

## 5. 상품권 교환

- 발송은 사람이 한다: 수익 → 교환 요청에서 발송 처리 또는 반려(포인트가 돌아간다).
- 받는 번호는 발송에만 쓴다. 처리 30일 뒤 배치가 끝 4자리만 남기고 가린다 — 그 전에 발송 누락 문의를 마무리한다.
- 발송 대기 교환이 남아 있는 제작자는 탈퇴할 수 없다. 탈퇴 문의가 오면 발송·반려를 먼저 끝낸다.

## 6. 탈퇴·계정

- 탈퇴는 유저가 직접 한다. 계정은 익명화되고 대화·페르소나·댓글·만든 세계관이 지워진다. 결제 기록은 5년 보관된다.
- 같은 이메일은 7일 동안 재가입할 수 없다.
- 운영자가 "탈퇴" 상태를 직접 넣지 않는다 — 상태만 바뀌고 개인정보가 지워지지 않는다. 정지·영구 정지를 쓴다.
